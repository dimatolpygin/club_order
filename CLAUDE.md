# CLAUDE.md — Telegram-бот клуба «11:11»

Чат-бот онлайн-клуба с ежемесячной подпиской: приём заявок, оплата через ЮKassa,
авто-управление доступом в закрытую группу, напоминания о продлении.

## Старт сессии (обязательно)

Перед любой работой выполнить ритуал okplan:
1. Прочитать `docs/STATUS.md` — текущий этап, активная работа, блокеры.
2. `git tag -l "stage-*"` — сверить с колонкой «Закрывающий тег» в STATUS. Тег без записи в таблице = STATUS устарел, сначала починить.
3. `git log --oneline -10` — что менялось последним.
4. Открыть `docs/07_ROADMAP.md` на текущем этапе — там чекбоксы открытых acceptance-пунктов.

Прогресс ведётся по методологии **okplan** (три слоя правды: STATUS.md → чекбоксы ROADMAP → git-теги `stage-N-done`). Тег ставится только после живой верификации человеком. Не отмечать чекбоксы и не ставить теги наперёд.

## Архитектурные решения (зафиксированы с заказчиком)

- **Цены подписки — две ставки: вход и продление (актуально с этапа 43, цикл 3).** Авто-ступени по числу занятых мест **убраны совсем** (упрощение цикла 1). В `bot_settings` две цены ₽/мес: `subscription_entry_price` (вход — новичок / после перерыва) и `subscription_renewal_price` (продление — непрерывный подписчик). **Пользователь видит ТОЛЬКО длительности** (1/3/6/12 мес) с ценой = ставка × месяцы. Регулировка стоимости для первых участников — **промокодами** (этап 7). Цены правит админ в веб-админке «Тарифы». Движок — `services/tariffs` (`entry_rate`/`renewal_rate`, `get_current_tier` отдаёт синтетическую «ступень» с ценой входа, `tier_id`=NULL); `price_tiers`/`tier_prices` в БД сохранены только под историч. FK, ценой не управляют.
  - _История: до этапа 43 цена считалась авто-ступенями-брекетами по местам (первые 11 мест — X ₽/мес, места 12–22 — Y ₽/мес, …), ставка фиксировалась за юзером. Ступени были скрыты от пользователя. Отменено раундом 4 (11.07.2026), реализовано в этапе 43._
- **Фиксация цены**: за пользователем не фиксируется числовая ставка — «фиксация» = признак непрерывной подписки. Пока есть активная подписка (продление без перерыва) — платит цену **продления**; обрыв → активной подписки нет → новый вход по цене **входа**.
- **Закрытое пространство — группа (супергруппа с топиками)**: бот-админ одобряет join-request только оплатившим, кикает по окончании.
- **Оплата — ЮKassa без вебхука**: создание платежа + фоновый polling pending (домена нет). Чек 54-ФЗ: email-заглушка из настроек, но архитектурно заложен сбор/сохранение реального email (`users.email` + единая `build_receipt`).
- **Промокоды** — полноценно (этап 7).

### Обновление: билеты «Фокус.Энергия» + рефералка (зафиксировано с заказчиком 22.06.2026)

Бот становится двойным: подписка 11:11 (готово) + продажа билетов на офлайн-события (бани, ретриты). Детали — `docs/апдейт_этапы.csv`, `docs/вопросы_заказчику.md`.

- **Типы билетов**: мужской / женский / парный М+Ж / парный Ж+Ж / парный М+М. У каждого типа **своя цена** (задаёт админ). Гендер-баланс (галочка): места общие или раздельно М/Ж; парный М+Ж = 1М+1Ж, парный Ж+Ж/М+М = 2 места своего пола. Мест нет → «Мест нет» + кнопка «Запрос в Поддержку».
- **Показ событий**: ретриты — все; баня — только ближайшая (после даты — автопереключение/скрытие); галочка «Показывать заранее» — показать конкретную баню заранее.
- **После оплаты билета**: сообщение с правилами + 2 кнопки «С правилами согласен (показать адрес)» / «Есть вопросы». Адрес — после согласия. QR/номер не нужен. Билет НЕ даёт доступ в группу.
- **Скидка подписчикам на билеты**: настраивается **индивидуально на каждое мероприятие** (бани — общая, каждый ретрит — своя).
- **Стекинг скидок**: скидка подписчика и промокод НЕ суммируются → берём **максимальную** (меньшая итоговая цена). Бонусы суммируются с любым из них, но оплата бонусами **не более 50%** суммы. Порядок: сначала скидка/промокод, затем бонусы добивают до −50% от цены **со скидкой**.
- **Рефералка**: пока **только бани**. Ссылка `/ссылка`. Новичок (кто ещё ничего не покупал) — скидка (дефолт 500 ₽); пригласивший — бонус (дефолт 1000 ₽) **после даты мероприятия**. Суммы меняются в админке. 1 бонус = 1 ₽.
- **Возвраты/переносы**: кнопку «Перенос» НЕ делаем; возвраты только через менеджера, индивидуально, **ручным переводом** (ЮKassa-автовозврат отложен). Авто-движок правил возврата не нужен. «Мои билеты» — список активных (прошедшие скрыты).
- **Веб-админка**: отдельная панель на поддомене `admin.agat-key.ru` (мероприятия, цены, скидки, подписки, рефералка, кнопки меню, статистика — приоритет Доход за период со сравнением, общий и по направлениям). Текущую `/admin` в боте **замораживаем** — новый функционал только в вебе.

## Отладка и проверки (накоплено практикой — экономит время)

- **psql: база `postgres`, схема `club_bot`.** Базы `club_bot` НЕ существует — `-d club_bot` падает.
  Правильно: `docker compose exec -T postgres psql -U postgres -d postgres -c "SELECT ... FROM club_bot.<table>;"`
  (таблицы всегда с префиксом схемы, search_path в psql не выставлен).
- **Локальный dev сам применяет миграции.** В dev-стеке включён hot-reload: достаточно создать
  файл миграции — бот перезапустится и накатит её на локальную БД. **Пользуйся этим: любую
  миграцию сначала проверяй локально, только потом на прод.**
- **Запуск тестов**: `python -m tests.<name>`. Два подводных камня на Windows:
  - `PYTHONIOENCODING=utf-8` обязателен — иначе тесты с символами вроде `→` падают с
    `UnicodeEncodeError` (консоль cp1251), хотя логика в порядке;
  - тестам, которые импортируют `src.config`, нужны переменные окружения, иначе pydantic
    ругается на `database_url`: `DATABASE_URL="postgresql://x:x@localhost/x" BOT_TOKEN="1:x"`.
- **Диагностика на проде — прогон боевых функций на боевых данных.** Самый быстрый способ
  понять «баг или нет»: положить скрипт в контейнер и выполнить (`init_pool()` из `src.db`
  сам поднимет пул с нужным search_path):
  `docker compose cp diag.py bot:/app/diag.py && docker compose exec -T bot python diag.py`
  (после — удалить). Так снимаются споры «скидка не считается» за один заход.
- **Логи живут только с момента перезапуска контейнера.** После деплоя `docker compose logs`
  прошлое не покажет — если нужна история, снимай логи ДО выката.
- **Любой пуш в `master` = полный редеплой**, даже если изменены только `docs/`. Контейнеры
  bot/admin пересоздаются. Не страшно, но docs-коммиты лучше не сыпать по одному.
- **SSH на Windows/Git Bash** пишет `hostfile_replace_entries: mkstemp: Permission denied` —
  это безвредный шум про `known_hosts`, подключение при этом проходит.
- **Тестовые аккаунты**: `@Polarasing` id `2042819654` (рабочий, с историей покупок — годится
  как «пригласивший») и `@hochapuri_hot` id `8058822980` (тестовый). Для проверки рефералки
  нужны ДВА аккаунта, причём приглашённый должен быть **настоящим новичком** — `is_newbie`
  требует ноль подписок, ноль оплаченных билетов и ноль `succeeded`-платежей. Частая ловушка
  на приёмке: тестируют с аккаунта пригласившего и делают вывод «скидка не работает».
