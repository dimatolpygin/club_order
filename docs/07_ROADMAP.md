# Дорожная карта реализации — Telegram-бот клуба «11:11»

10 этапов от пустого репозитория до прод-готовности. Каждый этап заканчивается
**демонстрируемым результатом** (что можно потрогать руками в боте/на сервере).

Ключевая идея: **MVP-first**. Этап 1 = тонкая, но живая вертикаль (бот отвечает,
показывает экраны из навигации). Всё остальное наслаивается без перепиливания базы.

> **Где смотреть прогресс**: текущий статус всех этапов — в [`STATUS.md`](STATUS.md).
> Внутри каждого этапа ниже — чекбоксы конкретных acceptance-пунктов. Закрытие этапа
> сопровождается git-тегом `stage-N-done`.

> **Цикл 1 (этапы 0–10) — закрыт** (бот подписки 11:11 в проде). **Цикл 2 (этапы 11–21)** —
> обновление «Фокус.Энергия» (билеты, рефералка, скидки) + веб-админка. Детали цикла 2 —
> в конце файла (раздел «Цикл 2»).

## Базовые архитектурные решения (зафиксированы с заказчиком)

- **Модель цен — авто-ступени по местам, ступени СКРЫТЫ от пользователя.** Внутри —
  ценовые ступени-брекеты по числу занятых мест (первые 11 мест — 1111 ₽/мес, 12–22 —
  2222 ₽/мес, …, дальше «Стандарт»), значения/лимиты задаёт админ. Текущая помесячная
  ставка определяется АВТОМАТИЧЕСКИ по числу активных участников клуба: занято <11 →
  ставка ступени 1; с 12-го участника → ступень 2 и т.д. **Пользователь видит только
  длительности** (1/3/6/12 мес или строго 1) с ценой = текущая_ставка × месяцы — без
  каких-либо «ступеней» и чисел мест на экране. За пользователем фиксируется помесячная
  ставка на момент оплаты; итог к оплате = ставка × число месяцев.
- **Фиксация цены.** Пока юзер продлевает без перерыва — его ставка сохраняется. Перерыв
  (подписка закончилась и не продлена) → ставка сбрасывается, новая подписка по актуальной
  доступной ступени.
- **Закрытое пространство — группа (супергруппа с топиками).** Бот — админ группы,
  одобряет join-request по инвайт-ссылке только оплатившим, кикает по окончании подписки.
- **Оплата — ЮKassa, без вебхука.** Создание платежа + фоновый polling pending-платежей
  (домена нет). Чек 54-ФЗ: email-заглушка из настроек, но архитектурно заложен сбор и
  сохранение реального email клиента (колонка в БД + единая точка формирования receipt).
- **Промокоды — полноценно в MVP** (отдельный этап).
- **Стек**: Python 3.12, aiogram 3, Postgres 16 (отдельная схема `club_bot`, чужие таблицы
  не трогаем), Redis (FSM + кеш), Loguru, Alembic (автоприменение миграций при старте),
  APScheduler (напоминания + polling платежей + проверка окончаний), Docker/Compose,
  hot-reload в dev, polling, CI/CD GitHub Actions → репо `dimatolpygin/club_order`.

## Этап 0 — Каркас репозитория

**Цель**: пустой, но рабочий проект, в котором есть вся инфраструктура для следующих этапов.

**Что делаем**:
- Структура `src/` (config, logger, db, cache, main, handlers/, services/), `migrations/` (Alembic), `docs/`.
- `config.py` на pydantic-settings: токен, admin_ids, схема БД `club_bot`, DSN Postgres/Redis, настройки ЮKassa, email-заглушка для чека.
- Логирование через **Loguru**: каждое действие пользователя (входящие, кнопки, команды) с датой/временем, username, user_id, first_name и текстом ответа — на русском.
- Пул Postgres (asyncpg) с `search_path=club_bot,public` — чужие таблицы не задеваются.
- Redis-подключение, RedisStorage для FSM.
- **Alembic** настроен на схему `club_bot`, автоприменение `upgrade head` при старте.
- Dockerfile, `docker-compose.yml` (прод: бот+pg+redis), `docker-compose.dev.yml` (локально, без проброса портов pg/redis на хост — на ПК уже заняты).
- Hot-reload в dev (watchfiles/`watchmedo`) — аналог `npm run dev`.
- `/start` отвечает заглушкой, бот работает в режиме polling.

**Критерии приёмки** (закрытие → tag `stage-0-done`):
- [x] `docker compose -f docker-compose.dev.yml up --build` поднимает бот + Postgres + Redis без ошибок
- [x] Alembic при старте создаёт схему `club_bot` и применяет миграции (в логе видно `upgrade head`)
- [x] Существующие чужие таблицы в БД на ПК не затронуты (бот работает только в схеме `club_bot`)
- [x] `/start` в боте отвечает заглушкой, в консоли — лог на русском с username/user_id/first_name/текстом ответа
- [x] Изменение `.py`-файла в dev пересобирает/перезапускает бота без ручного рестарта

## Этап 2 — Тарифы и места (админ-конфигурируемые)

**Цель**: динамический экран тарифов с лимитами мест и редактированием админом на лету.

**Что делаем**:
- Таблицы: `price_tiers` (название, помесячная ставка, лимит мест-брекет, порядок, активность), `durations` (месяцы, активность), `subscriptions` (для подсчёта активных участников).
- **Движок текущей ставки**: считает активных участников клуба и по кумулятивным брекетам ступеней определяет текущую помесячную ставку (занято <11 → ступень 1; 12-й участник → ступень 2; …; дальше «Стандарт»). Ступени пользователю НЕ показываются.
- Экран подписки: пользователь видит только **длительности** (1/3/6/12 мес), цена кнопки = текущая_ставка × месяцы. Цена меняется сама при заполнении мест.
- Админка — **пошаговый FSM-сценарий** (инлайн-меню → «введите цену», «введите лимит» и т.п.): правка цен/лимитов/активности ступеней, длительностей, ручное добавление участника. Изменения без перезапуска (кеш в Redis с инвалидацией).

**Критерии приёмки** (закрытие → tag `stage-2-done`):
- [x] Пользователь видит только длительности с ценой (без ступеней/чисел мест), цена = текущая ставка × месяцы
- [x] Текущая ставка определяется автоматически по числу активных участников (при заполнении мест ступени цена сама перескакивает на следующую)
- [x] Админ через пошаговый FSM-сценарий меняет цену/лимит ступени → цена на экране подписки обновляется без рестарта
- [x] Админ включает/выключает длительности (например, оставить только 1 мес) → на экране остаются только активные
- [x] Итоговая сумма к оплате = текущая ставка × число месяцев (видно на экране сводки)

> Сверх плана этапа (по запросу заказчика, объём этапа 8 вынесен раньше): админ-карточка участника (поиск по tg_id, статус подписки/доступа), рассылка по базе (без фото), аннулирование подписки участника.

## Этап 3 — Оплата через ЮKassa + polling pending

**Цель**: реальная оплата создаёт активную подписку с зафиксированной ценой.

**Что делаем**:
- Создание платежа ЮKassa (idempotence key, amount, capture, return_url, metadata: tg_id/tier/duration), сохранение `yookassa_payment_id`, `confirmation_url`, статуса.
- `receipt` с email: заглушка из настроек, но через единую функцию `build_receipt(user)` с колонкой `users.email` — точка лёгкой замены на реальный сбор.
- Экраны: «Оплата» [Оплатить][Проверить оплату][Отмена], «Оплата в ожидании», «Успех», «Ошибка».
- Таблицы `payments` и `subscriptions` (tg_id, tier_id, fixed_price, start_date, end_date, status).
- Фоновый poller (APScheduler) опрашивает pending-платежи ЮKassa; при `succeeded` → активирует подписку (start=now, end=start + месяцы), пишет зафиксированную помесячную ставку.
- Кнопка «Проверить оплату» дёргает проверку немедленно.

**Критерии приёмки** (закрытие → tag `stage-3-done`):
- [x] «Оплатить» создаёт платёж в ЮKassa и выдаёт ссылку на оплату
- [x] После реальной тестовой оплаты подписка активируется (запись в `subscriptions` с start/end/fixed_price видна по SQL)
- [x] Polling сам подхватывает оплаченный платёж без нажатия «Проверить оплату» (в пределах интервала)
- [x] «Моя подписка» показывает статус/даты/зафиксированную цену/дни до конца
- [x] Повторная оплата того же платежа не создаёт дубль подписки

> Сверх плана этапа (по запросу заказчика на живом тесте): (1) цена за период —
> МАТРИЦА ступень×период (админ задаёт абсолютную цену за 3/6/12 мес в каждой ступени,
> иначе fallback ставка×месяцы; миграция 0004 `tier_prices`); (2) у оплативших «Вступить
> в клуб» ведёт на «Мою подписку», а не на тарифы; кнопка «Перейти в закрытый чат» из
> `CLUB_CHAT_INVITE_URL` (авто-одобрение заявок — этап 4); (3) команда `/sub` + меню
> команд бота (`/start`, `/menu`, `/sub`).

## Этап 5 — Фиксация цены, продление, авто-удаление

**Цель**: жизненный цикл подписки — продление с сохранением цены и удаление при обрыве.

**Что делаем**:
- Экран «Продление»: оплата по зафиксированной ставке; продление до окончания срока сохраняет цену (end_date += месяцы от старого end).
- Фоновая проверка окончаний (APScheduler): подписка истекла → статус `expired`, кик пользователя из группы, **сброс зафиксированной цены** (следующая подписка — по актуальной ступени).
- Экран «Подписка закончилась», «нет активной подписки».

**Критерии приёмки** (закрытие → tag `stage-5-done`):
- [x] Продление до конца срока сохраняет зафиксированную цену (видно по SQL: fixed_price не изменился, end_date продлён)
- [x] По истечении подписки бот автоматически кикает пользователя из группы
- [x] После обрыва подписки новая оформляется по актуальной ступени (старая цена не действует)
- [x] «Моя подписка» для неактивного показывает экран «нет активной подписки»

# Цикл 2 (v2) — «Фокус.Энергия» (билеты) + реферальная программа + веб-админка

MVP-first сохраняется: каждый этап заканчивается тем, что можно потрогать руками.

Источники требований: `docs/апдейт_этапы.csv` (для заказчика), `docs/вопросы_заказчику.md`

## Базовые решения цикла 2 (зафиксированы с заказчиком 22.06.2026)

- **Типы билетов**: мужской / женский / парный М+Ж / парный Ж+Ж / парный М+М — у каждого
  **своя цена** (задаёт админ). Гендер-баланс (галочка события): места общие или раздельно М/Ж;
  парный М+Ж = 1М+1Ж, парный Ж+Ж/М+М = 2 места своего пола. Мест нет → «Мест нет» + кнопка
  «Запрос в Поддержку».
- **Показ событий**: ретриты — все; баня — только ближайшая (после даты — автопереключение/
  скрытие); галочка «Показывать заранее» — показать конкретную баню заранее.
- **После оплаты билета**: сообщение с правилами + 2 кнопки «С правилами согласен (показать
  адрес)» / «Есть вопросы». Адрес — после согласия. QR/номер не нужен. Билет НЕ даёт доступа
  в группу (она открытая).
- **Скидка подписчикам на билеты**: индивидуально на каждое мероприятие (бани — общая,
  каждый ретрит — своя).
- **Стекинг**: скидка подписчика и промокод НЕ суммируются → берём **максимальную** (меньшая
  итоговая цена). Бонусы суммируются с любым из них, оплата бонусами **не более 50%**. Порядок:
  сначала скидка/промокод, затем бонусы до −50% от цены со скидкой.
- **Рефералка**: пока **только бани**. `/ссылка`: новичок (кто ещё ничего не покупал) — скидка
  (дефолт 500 ₽); пригласивший — бонус (дефолт 1000 ₽) **после даты мероприятия**. Суммы — в
  админке. 1 бонус = 1 ₽.
- **Возвраты/переносы**: кнопки «Перенос» нет; возвраты только через менеджера, индивидуально,
  ручным переводом (ЮKassa-автовозврат отложен). Авто-движок правил не делаем.
- **Веб-админка**: отдельная панель на `admin.agat-key.ru`, общая БД (схема `club_bot`).
  Дизайн: светлая, сайдбар слева, база чёрный+белый, показатели/графики — синий+зелёный,
  кастомные иконки, **без смайлов и фиолетовых градиентов**, законченный UX (вход/выход/смена
  пароля, нет нерабочих кнопок), человеческие формулировки (не сырые данные/переменные).
  Текущую `/admin` в боте **замораживаем** — новый функционал только в вебе.
- **Сервер**: `163.5.153.150` (2 CPU / 2 ГБ + swap), запас под админку есть. Стек — общий
  Docker Compose (добавляется сервис веб-админки + Nginx/Let's Encrypt для https).
